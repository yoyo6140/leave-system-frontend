## 登入

用 JWT 登入。原本是用 httpOnly cookie，但因為部署的前後端網址不同（不同網域），結果在 iOS 的 web 上，請求直接被 Safari 擋下——實測後端雖然有回 cookie，但 Safari 的跨站 cookie 限制讓前端完全拿不到，所以後來改成單純用 JWT 認證，不依賴 cookie。

密碼規則是 6～12 字元，另外加了一個顯示密碼的按鈕，讓使用者可以切換要不要看到自己打的密碼。

目前系統設計上只有一個管理員帳號，管理全部員工（還沒有多管理員分權的情境）。

→ 對應正式規格：`02-login.md`、`01-summary.md` §6

## 請假額度怎麼存

一開始想得太簡單，發現**不能單純把員工的假別額度當成一筆固定資料存起來**——因為特休會隨年資變動，不是存一個數字就能一直用。

另外一個卡關的地方：如果不想串接行事曆（也就是不知道哪些天是例假日、國定假日），那系統就沒辦法自動幫員工算「請 3 天假等於幾個工作日」。所以做法是反過來：**讓員工自己圈選請假的日期範圍，自己說明這段時間要請多少時數**，系統不自動幫你扣例假日，時數由員工自己填、自己負責。

額度這塊後端是**動態計算**（依到職日、年資即時換算），不是前端存一份死數字——這樣比較有效率，也比較不會因為資料沒同步而算錯。

→ 對應正式規格：`07-leave-balance.md`、`08-apply.md`、`01-summary.md` §8（時數換算）

## Overview（總覽）

分三個區塊：

1. 第一區是小卡片，顯示「待審核案件」「本月已核准」「員工人數」三個數字。
2. 第二區顯示目前待審核的請假清單，旁邊加一個「前往審核」的按鈕。
3. 第三區統計每個員工的年請假總時數，讓管理者可以直觀地注意到「這個員工請假是不是有點異常」（例如請太多次、或某人特別多）。

→ 對應正式規格：`03-overview.md`

## 審核管理 / 假別定義

假別要先定義好，一共七種：**特休 / 病假 / 事假 / 婚假 / 喪假 / 公假 / 其他**。

其中「特休、病假、事假、婚假、喪假」這五種都是根據勞基法（含勞工請假規則）訂的規則，有明確天數/時數上限。

「公假、其他」這兩種設計成**無上限**——用來應對「上述規則沒有涵蓋到」的情況，不然遇到法規沒列出來的請假事由，系統會卡住沒地方放。

假別餘額是**動態生成**的：根據員工的年資去換算成對應的時數，不是手動設定好就不會變。

→ 對應正式規格：`06-review.md`（審核）、`07-leave-balance.md`（假別餘額）、`11-labor-law.md`（假別法規對照）

## AI 分析

這個功能主要是練習怎麼串接 AI 模型的 API。用預先設定好的提示詞（system prompt）限制住，避免使用者拿這個聊天框去問跟系統無關的事情。

選擇用「問答不留紀錄」的方式設計，好處是使用者可以直接切換話題去問，不用擔心前面問的東西會卡在對話歷史裡影響後面的回答，而且不留紀錄代表不用額外處理歷史對話的儲存跟隱私問題。

→ 對應正式規格：`10-ai-analysis.md`
